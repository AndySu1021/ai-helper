# Brainstorm — 需求討論

與使用者進行結構化需求討論，釐清範圍與邊界條件，**不產出實作細節或程式碼**。

## 使用方式

```
/brainstorm
```

---

## 步驟 0：讀取 ticket-id

```bash
TICKET_ID=$(cat tmp/.current-ticket)
```

輸出路徑為 `tmp/${TICKET_ID}/requirements.md`。

---

## 步驟 1：載入專案背景

讀取以下檔案（若存在）以了解專案背景：
- `CLAUDE.md` — 專案規範
- `tmp/${TICKET_ID}/` 目錄下的既有文件

---

## 步驟 2：釐清需求

使用 `AskUserQuestion` 詢問：

> 請描述你想實作的功能或需要解決的問題。若有 Jira ticket 或 Confluence 文件，也請一併提供。

收到描述後，逐一確認以下問題（有不清楚的就問，不可自行假設）：

1. **目標**：這個功能要達到什麼目的？成功的標準是什麼？
2. **範圍**：哪些東西包含在這次實作內？哪些明確排除？
3. **使用者**：誰會使用這個功能？有什麼前置條件？
4. **邊界條件**：有哪些特殊情境需要處理？（nil 值、空資料、大量資料、並發）
5. **相依性**：是否依賴其他系統或服務？（API、資料庫、第三方服務）
6. **限制**：有效能、安全、法規或時程的限制嗎？

**必須遵守**：若上述問題中有任何無法從使用者回應得到明確答案的，以條列方式列出「待確認項目」，並再次詢問，不可跳過。

---

## 步驟 3：方案討論

根據需求描述，提出 **至少 2 個不同實作方向**，每個方向包含：

- **名稱**：簡短的方案名稱
- **描述**：這個方向的做法
- **優點**：具體好處
- **缺點**：具體限制或風險
- **複雜度估計**：低 / 中 / 高

使用 `AskUserQuestion` 詢問使用者偏好的方向，並說明原因。

---

## 步驟 4：確認並輸出摘要

討論收斂後，使用 `AskUserQuestion` 顯示摘要預覽並確認：

```
══════════════════════════════════
需求摘要
══════════════════════════════════
功能名稱：<名稱>

目標：
<清楚描述要達成什麼>

範圍內：
- <項目 1>
- <項目 2>

範圍外（明確排除）：
- <項目 1>

邊界條件：
- <需要特別處理的情境>

選定方向：<方案名稱>
理由：<為何選此方向>

待確認項目：（若有）
- <問題 1>

資料來源：<Jira 連結或 Confluence 連結>
══════════════════════════════════

確認內容正確嗎？若有需要修正的地方請說明。
```

確認後，將摘要**寫入 `tmp/${TICKET_ID}/requirements.md`**：

```markdown
---
stage: requirements
status: confirmed
created: <YYYY-MM-DD>
source: <Jira 連結或 Confluence 連結，若無則留空>
---

# 需求摘要：<功能名稱>

## 目標

<清楚描述要達成什麼>

## 範圍內
- <項目 1>

## 範圍外（明確排除）
- <項目 1>

## 邊界條件
- <需要特別處理的情境>

## 選定方向

**<方案名稱>**：<為何選此方向>

## 待確認項目（若有）
- <問題 1>
```

寫入後告知使用者：

```
需求摘要已儲存至 tmp/<ticket-id>/requirements.md。

建議後續步驟：
  /plan-writer      制定實作計畫
```

---

## 規則

- **禁止產出任何程式碼或偽代碼**，實作細節留給 plan-writer 和 implementer。
- 未釐清的問題必須列出並詢問，不可自行補假設繼續。
- 若使用者提供的資訊來自 Jira 或 Confluence 但無法存取，明確告知並請使用者提供內容。
- **摘要必須寫入 `tmp/${TICKET_ID}/requirements.md`**，不可只輸出到對話。
